# UX-038 — Éviter les saisies répétées dans un même processus

Type : Anti-pattern et remplacement · Version : 1.0 · Revue documentaire : 2026-09-07

## Problème
Une adresse déjà fournie est demandée de nouveau.

## Bonne pratique
3.3.7 A prévoit de préremplir ou rendre sélectionnable une information déjà fournie dans le même processus, sauf exception.

Source du principe : [W09 — W3C Understanding — 3.3.7 A — redundant-entry](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html). Nature : Norme expliquée.

## Pourquoi
La répétition augmente effort et erreurs.

## À faire
- Réutiliser les données connues
- Permettre leur correction

## À éviter
Demander deux fois le même renseignement sans besoin.

## Exceptions et limites
Exceptions : nouvelle saisie essentielle, sécurité ou information devenue invalide ; le critère ne couvre pas automatiquement tous les retours intersessions.

## Exemple original, fictif
Bon : « Utiliser cette adresse ». Mauvais : recopier tous les champs de livraison.

## Checklist de vérification
- [ ] Parcourir les étapes avec une valeur connue
- [ ] Vérifier sa correction et sa réutilisation
- [ ] Conserver une preuve du résultat (capture, observation ou relevé) et les limites du test.

## Confiance et provenance
Élevée sur le critère cité ; application à vérifier dans le produit. Statut de consultation : Contenu consulté, le 2026-09-07.
La règle reprend le principe référencé. L’exemple, les actions et le protocole de test sont des adaptations originales ; ils ne constituent pas une étude publiée ni un résultat déjà observé.
