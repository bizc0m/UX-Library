# UX-022 — Adapter la disposition à la fenêtre disponible

Type : Bonne pratique · Version : 1.0 · Revue documentaire : 2026-09-07

## Problème
Une tablette en fenêtre étroite reçoit une interface trop large.

## Bonne pratique
Choisir la disposition selon l’espace réel disponible, pas uniquement le type d’appareil.

Source du principe : [M01 — Android Developers — Material 3 adaptive / Window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes). Nature : Recommandation.

## Pourquoi
Le multitâche et le redimensionnement changent l’espace pendant l’usage.

## À faire
- Prévoir une et deux colonnes selon le besoin
- Préserver sélection et saisie lors du changement

## À éviter
Détecter « tablette » et imposer deux panneaux.

## Exceptions et limites
Les classes Material/Android utilisent des dp ; ne pas copier ces nombres comme règles universelles en pixels CSS ou points Apple.

## Exemple original, fictif
Bon : liste puis détail en fenêtre étroite. Mauvais : tableau tronqué sur tablette partagée.

## Checklist de vérification
- [ ] Redimensionner pendant une édition
- [ ] Vérifier clavier affiché et petite hauteur
- [ ] Conserver une preuve du résultat (capture, observation ou relevé) et les limites du test.
